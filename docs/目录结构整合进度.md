# 目录结构整合进度

## 目标

把 `Clipboard` / `NetworkWatch` / `ProcessWatch` / `MenuManager` / `Translator` / `LavaEnv`
六个独立工程并入 `DevBox.Core`（业务逻辑）与 `DevBox.Host`（界面），最终解决方案只保留：

- `DevBox.Core/`
- `DevBox.Host/`

目录风格对齐 `D:\Fireneb\DevTools\SigXor`：功能域是工程内子目录，**命名空间与目录一致**。

## 统一约定

| 项 | 约定 |
|----|------|
| 命名空间 | 模块代码统一改为 `DevBox.Core.<模块>.*`（如 `DevBox.Core.NetworkWatch.Services`）；Host 内的 UI 代码统一为 `DevBox.Host.*` |
| 目录 | `DevBox.Core/<模块>/{Models,Services,...}`，保留模块内部原有分层 |
| 删除 | 模块目录下的 `.csproj`、`.sln`、`.gitignore`、`AssemblyInfo.cs`、`app.manifest` 等工程级文件；`bin/obj` 产物不入库 |
| 资源 | LavaEnv 的 `Resources/`（含故意入库的 `tools/7zr.exe`）随代码迁入 `DevBox.Core/LavaEnv/Resources/`，csproj 的 Content 规则同步更新 |
| 文档 | 模块 README / CHANGELOG 的内容并入 `docs/` 或删除（批次内判断），主 `CHANGELOG.md` 在收尾批次统一补条目 |
| 构建 | 每批结束必须 `dotnet build DevEnv.sln -c Debug` 通过 |
| 提交 | 每批通过构建后按仓库规范用中文提交一次（**不加任何 AI 署名**） |

## 每批固定流程

1. `git mv` 文件到目标目录（保留历史）
2. 批量改命名空间与 using（只改 `namespace` / `using` 行，不动字符串字面量与注释）
3. 迁移 csproj 的 PackageReference / Content 规则到 `DevBox.Core.csproj`，删除模块 csproj 及 ProjectReference
4. 从 `DevEnv.sln` 移除对应工程
5. `dotnet build DevEnv.sln -c Debug` 验证
6. 更新本文件状态并提交
